# md-pdf-editor

MarkdownまたはHTML(+CSS)を取り込み、プレビューを見ながら編集し、**元のファイルとPDFを同時に出力**する単体アプリです。
Dockerだけで動き、Windows / macOS / Linux(x86_64・arm64)で同じ手順で使えます。

## 起動

必要なものは Docker(Docker Compose v2)だけです。

```bash
docker compose up -d --build
```

ブラウザで **http://localhost:8088** を開きます(Chrome または Edge)。
停止は `docker compose down` です。

> `-d` を付けずに `docker compose up` すると、そのターミナルで Ctrl+C を押した時点でコンテナも停止します(ブラウザから接続できなくなります)。普段は `-d` 付きで起動してください。
> WSL2 上で動かしている場合も、Windows のブラウザから `http://localhost:8088` で開けます。

設定を変える場合は `.env.example` を `.env` にコピーして編集します(ポート番号など。下記「設定」)。

## 使い方

1. **取り込み**: Markdown(.md / .markdown / .txt)またはHTML(.html / .htm)のファイルをドラッグ&ドロップ、または「ファイルを選択」。貼り付けも可能です(Markdown / HTMLを選びます)。UTF-8以外のファイルは、文字化けさせずにエラーにします。
   - **HTMLにCSSを使う場合**は、HTMLと一緒にCSSファイル(.css)も選びます(複数選択・複数ドロップ)。HTMLの `<link rel="stylesheet" href="…">` と**ファイル名が同じ**CSSが適用されます(フォルダ名は無視します。例: `css/style.css` と書かれていれば `style.css`)。
   - 取り込める文書は1つだけです(HTMLが2つ、Markdownと一緒にCSS、などはエラーにします)。
2. **編集(Markdown)**: 「プレビュー(書式付きで編集)」で、見出し・表・箇条書き・コードを見た目のまま編集できます。「Markdown」タブでは、元のMarkdownを直接編集できます。タブを切り替えると、編集内容が引き継がれます。
   **編集(HTML・CSS)**: 次の3種類のタブで編集できます。
   - 「プレビュー(直接編集)」: 表示を見ながら、文字を直接編集できます。上のボタンで、元に戻す・太字・斜体・下線・見出し・段落・箇条書きも使えます。**編集した箇所のHTMLだけが書き換わり、編集していない部分は、取り込んだまま(インデント・引用符・実体参照・コメントなど)です**。貼り付けは、他のページの書式を持ち込まないよう、文字だけになります。
   - 「HTML」「CSS: ファイル名」: ソースを直接編集します。隣のプレビューに、入力内容がすぐ反映されます。
   - タブを切り替えると、編集内容が引き継がれます。表の行や列の追加など、プレビューでできない操作は、「HTML」タブで行ってください。
3. **出力**: 「保存するファイル」で、保存するものをチェックで選びます(Markdownなら Markdown (.md) と PDF (.pdf)、HTMLなら HTML (.html)・CSS(取り込んだファイルごと)・PDF (.pdf))。先にファイル名(拡張子なし)を決めてから、保存します。保存方法は次の2つで、1つだけ保存する場合も同じです(保存されるのは、チェックしたファイルだけです)。CSSは、HTMLから参照されている名前(`style.css` など)のまま保存します(ファイル名の指定は、CSS以外に使います)。
   - **選んだフォルダへ出力**: 「出力先フォルダを選択」→「選んだフォルダへ…を出力」(両方なら「MDとPDF」、片方なら「MD」または「PDF」)。好きなフォルダに直接書き込みます。保存するファイルと同名のファイルがある場合は、上書きするか確認します。
   - **ダウンロードで保存**: ブラウザのダウンロードとして保存されます(保存先はブラウザの設定に従います)。フォルダ選択の制限を受けず、どのブラウザ・どの接続方法でも使えます。複数ファイルのダウンロードを確認されたら、許可してください。

   「PDFを生成して確認(新しいタブ)」で、出力前にPDFの見た目を確認できます。

## 動作環境と制約

- **「選んだフォルダへ出力」は Chrome / Edge 限定**です(ブラウザのFile System Access APIを使うため)。Firefox・Safari では、このボタンが無効になり理由が表示されます。その場合は「ダウンロードで保存」を使ってください。
- **`http://localhost:ポート` でアクセス**してください。`http://192.168.x.x:ポート` のようなIPアドレスでのアクセスでは、ブラウザの仕様でフォルダ選択が使えません(「ダウンロードで保存」は使えます)。別のPCで動かしているコンテナを使う場合は、SSHのポート転送(`ssh -L 8088:127.0.0.1:8088 <ホスト>`)で、手元の `localhost:8088` から開くと、フォルダ選択も使えます。
- Chrome / Edge は、システムデータを含むフォルダ(`ドキュメント` / `ダウンロード` / `デスクトップ` のフォルダそのもの、ホームフォルダ、`AppData` など)を、出力先として選ぶことを拒否します(「システムデータが含まれているため…」と表示されます)。これはブラウザのセキュリティ機能で、アプリからは解除できません。次のどちらかで保存してください。
  - その中に**新しいフォルダを作って**、そのフォルダを選ぶ(例: `ドキュメント` の中に `md-pdf` フォルダを作る)
  - 「ダウンロードで保存」を使う
- 認証機能はありません。既定ではこのPCからのみ接続できます(`BIND_ADDR`)。

## PDF・Markdownの扱い

- PDFはサーバ側のChromiumで、MarkdownからA4縦(余白20mm、フッターにページ番号)で生成します。日本語はNoto Sans CJK JPの字形です。プレビューはお使いのOSのフォントで描画されるため、字形や折り返し位置、改ページ位置が少し異なることがあります。
- **生HTML**(`<br>`、`<div>`、`<!-- コメント -->` など)は、実行も削除もせず、**文字としてそのまま表示**されます。出力前に画面に警告が出ます。
- **画像**は、`data:image/...;base64,...`(png・jpeg・gif・webp)だけがPDFに表示されます。それ以外は `[画像: 代替文](URL)` という文字になります(外部へは通信しません)。出力前に警告が出ます。
- リンクは http / https / mailto / tel と相対URLだけ有効です。`javascript:` などは `文字 (URL)` になります。
- 先頭の **front matter**(YAML)は、PDFにYAMLのコードブロックとして表示されます。
- 段落内の改行は、すべて改行として扱います(プレビューの表示と揃えるため)。
- 表として成立しない「|」付きの行がある場合は、警告が出ます。

### HTMLの扱い

- PDFは、MarkdownのときのようなアプリのCSSは使わず、**取り込んだHTMLとCSSの見た目のまま**になります(CSSは、HTMLの `<link>` の位置に埋め込んでから描画します。参照する `<link>` が無いCSSは、`<head>` の末尾に追加して適用します。保存する `.html` には埋め込みません)。
- 用紙は既定でA4縦(余白20mm、フッターにページ番号)です。CSSの `@page { size: A5 landscape; }` などで用紙サイズを指定すると、それに従います。
- **JavaScriptは実行しません**(プレビュー・PDFとも)。`<script>` やイベント属性(`onclick` など)は動かず、JavaScriptで作られる内容は表示されません。`<noscript>` の内容は、そのまま表示されます。
- **外部へは通信しません**。画像・CSS・Webフォント・`@import`・`url(…)` で、`http(s)://` や相対パスのファイルを指しているものは、表示されません(`data:` のURIだけ表示されます)。出力前に警告が出ます。画像は、`data:image/…;base64,…` の形で埋め込んだものだけ表示されます。`<meta http-equiv="refresh">`(自動で別ページへ移動)は、無視します。
- 文字は、サーバ側のフォント(Noto Sans CJK JPなど)で描画されます。`font-family` で指定したフォントがサーバに無い場合は、代わりのフォントになります(Webフォントは `data:` のURIで埋め込んだ場合だけ使えます)。
- UTF-8のHTMLだけ取り込めます。Shift_JISなどのHTMLは、UTF-8に変換してから取り込んでください(`<meta charset>` の宣言とファイルの文字コードが食い違うと、文字化けするため)。
- プレビューでの編集は、編集後の表示をブラウザが解釈し直した内容を、元のHTMLと見比べて、違う部分だけを書き換えます。段落の分割(Enter)・太字などで構造が変わった場合は、その段落(の範囲)のHTMLが、ブラウザの出力する形(属性は二重引用符、`&nbsp;` など)に変わります。それ以外の部分は変わりません。

### 書式付きで編集したときの正規化(Markdown)

「プレビュー」で**一度でも編集すると、Markdown全体の書き方が正規化**されます。内容(文字)は保たれますが、書き方は次のように変わります。編集しなければ、取り込んだMarkdownはそのまま出力されます。

- 箇条書きの記号は `*`、水平線は `***`、強調は `**太字**` / `*斜体*` になる
- 番号付きリストの開始番号は1始まりになる(`3.` から始めても `1.` になる)
- 表の桁が揃えられる
- Setext見出し(`===` の下線)はATX見出し(`#`)になる。`~~~` のコードフェンスは ``` になる
- インデントによるコードブロックは、通常の段落になる
- 行末の強制改行マーカー(行末の空白2つ・`\`)は消える(改行そのものは残る)
- HTMLエンティティ(`&amp;` など)は文字に戻る。裸のURLはリンク記法になる
- 元から `\<` と書かれていた箇所は `<` になる

### 書式付きで扱えない記法

**脚注**(`[^1]`)と**参照形式のリンク**(`[文字][id]` + `[id]: URL`)は、書式付きエディタが解釈できません。含まれている場合は、その旨を表示して「Markdown」タブへ切り替わります。PDFは通常どおり出力できます。

## 設定

`.env`(`.env.example` をコピー)で設定します。すべて省略可能です。

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `HOST_PORT` | `8088` | ブラウザで開くポート番号 |
| `BIND_ADDR` | `127.0.0.1` | 接続を受け付けるアドレス。LAN内の他のPCにも公開する場合は `0.0.0.0`(認証が無いため信頼できるネットワークのみ) |
| `MAX_MARKDOWN_BYTES` | `5242880` | 受け付けるMarkdown・HTMLの最大サイズ(バイト) |
| `PDF_TIMEOUT_MS` | `60000` | PDF生成のタイムアウト(ミリ秒) |

## API

画面を使わずに、PDFだけ生成することもできます。`markdown` または `html` のどちらか一方を指定します。

```bash
curl -X POST http://localhost:8088/api/pdf \
  -H 'Content-Type: application/json' \
  -d '{"markdown": "# 見出し\n\n本文"}' \
  -o out.pdf

# HTML(CSSは <style> で埋め込んだもの。外部ファイルは読み込まれません)
curl -X POST http://localhost:8088/api/pdf \
  -H 'Content-Type: application/json' \
  -d '{"html": "<!DOCTYPE html><style>h1{color:#c00}</style><h1>見出し</h1><p>本文</p>"}' \
  -o out.pdf
```

エラー時は `{"error": {"code": "...", "message": "..."}}` を返します(400: 不正なリクエスト / 413: サイズ超過 / 500: PDF生成失敗)。`GET /healthz` は稼働確認用です。

## 構成と開発

- 1コンテナです。Express が、ビルド済みの画面(React + `@mdxeditor/editor`。HTMLの解析に `parse5`)の配信と、`POST /api/pdf` を提供します。
- PDF生成は、要求ごとにChromiumを起動・終了します(常駐させません)。同時に複数の要求が来た場合は、順番に処理します。描画するHTMLは、JavaScript無効・外部通信遮断の状態で処理します。
- 起動時にPDFを1本生成して、Chromiumとフォントが使えることを確認します。失敗した場合はコンテナが終了します(`docker compose logs` で原因を確認できます)。
- コンテナは、非root・読み取り専用ルート・全Capability削除で動きます。

テストは、Dockerの `test` ステージで実行します(型チェック → ビルド → 全テスト。実Chromiumを使う、PDF生成と画面操作の結合テストを含みます)。

```bash
docker build --target test -t md-pdf-editor:test .
```

### ディレクトリ

```
src/client/   画面(取り込み・編集・出力)と、Markdown・HTML(差分の反映 htmlPatch、CSSの埋め込み htmlCompose)・ファイル名・出力処理のロジック
src/server/   API、Markdown→HTML、Chromiumによる PDF生成、起動時セルフチェック
src/shared/   プレビューとPDFが共通で使うCSS(document.css)
tests/        PDF生成・画面操作の結合テスト(実Chromium)
```

### arm64(Apple Silicon、Linuxのarm64機)

同じ `docker compose up -d --build` で動く設計です(Debianのarm64版 `chromium` を使います)。実機での確認が必要な場合は、起動後に `docker compose logs` に「起動時セルフチェックOK」が出ること、および画面から出力したPDFの日本語が正しく表示されることを確認してください。
